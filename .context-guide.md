## 🎯 Daily Workflow

**Morning:** Read `context/roadmap/current-phase.md` → know today's focus
**During work:** Add bugs/features as discovered
**End of day:** Update `context/features/in-progress.md` with progress
**Friday:** Update `context/STATUS.md` with week's achievements

## 📝 Key Rules

1. **300-line limit per file** - Split if exceeded
2. **Use templates** - Found in `context/README.md`
3. **Update INDEX files** - When adding items
4. **Link related items** - Cross-reference bugs ↔ features
5. **Archive old items** - After 30 days of completion

## 🎓 Pro Tips

**Finding things fast:**
- Start with INDEX files
- Use Ctrl+F within files
- Check STATUS.md for overview

**Keeping organized:**
- Use provided templates
- Update as you go, not in batches
- Link between related items
- Clean up monthly

**Staying focused:**
- Current phase = this week's focus
- Don't over-plan distant future
- One file open = one focus area

## ✨ Why This System?

**Before:** Information scattered, hard to find, files too large
**After:** Organized, scannable, maintainable, scalable

**Design Principles:**
- 📏 **Small files** (max 300 lines) → easy to scan
- 🗂️ **Status-based** (in-progress/planned/ideas) → matches workflow
- 🧭 **INDEX files** → quick navigation
- 📋 **Templates** → consistency
- 🎯 **Focus on now** → detailed short-term, vague long-term

## 🚦 System Health

Check system health:
```bash
# Count files
find context -name "*.md" | wc -l

# Check for oversized files
for f in context/**/*.md; do
  lines=$(wc -l < "$f")
  if [ $lines -gt 300 ]; then
    echo "⚠️  $f: $lines lines"
  fi
done
```
