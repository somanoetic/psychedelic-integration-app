================================================================================
SCHEMA OVERVIEW
================================================================================

TABLE 1: checklist_template_items
- Purpose: Default template items (seed data)
- Rows: 18 items across 4 categories
- Access: Read-only for users, admin-managed

TABLE 2: session_checklists
- Purpose: Checklist instance header (1 per session)
- Relationships: Links to sessions table, cascades on delete
- Aggregate fields: total_items, completed_items (auto-maintained)

TABLE 3: session_checklist_items
- Purpose: Individual checklist items (template + custom)
- Relationships: Links to session_checklists and checklist_template_items
- Max items: 50 per checklist (enforced at app layer)

FUNCTIONS:
1. create_session_checklist(session_id, user_id) → UUID
   - Atomically creates checklist and clones template items
   - Idempotent (safe to call multiple times)

2. update_checklist_counters() → TRIGGER
   - Auto-runs on INSERT/UPDATE/DELETE of items
   - Keeps parent aggregate counters synchronized

3. delete_user_checklist_data(user_id)
   - GDPR-compliant deletion of all user checklist data
   - Requires authorization (self or admin)
